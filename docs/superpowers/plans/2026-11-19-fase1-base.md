# Shopymemes Fase 1 (Base) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que la tienda gaste lo mínimo posible de Firestore y de Hosting, sin cambiar lo que ve el cliente.

**Architecture:** Imágenes pesadas fuera de Hosting (Cloudinary). Los productos llevan `updatedAt` y `deleted`. Un script genera `catalog.json` estático; el navegador lo usa y solo pide a Firestore lo que cambió.

**Tech Stack:** HTML/JS sin compilar, Firebase Hosting + Firestore (Spark), Cloudinary Free, Node 20 (`node --test`).

**Spec:** `docs/shopymemes-v2-design.md`

## Global Constraints

- No cambiar el stack: HTML + Bootstrap 5 + JS vanilla, sin frameworks ni paso de compilación.
- Todo gratis (plan Spark, Cloudinary Free).
- Los límites de `Public/shared.js` (`LIMITS`) y `firestore.rules` deben coincidir (`npm test` lo verifica).
- `updatedAt` = entero en milisegundos (`Date.now()`); `deleted` = booleano opcional.
- Nunca leer ni subir `.env` ni `serviceAccountKey*.json`.
- Antes de desplegar: `npm test`, vista previa en `127.0.0.1:3000`, y `firebase hosting:channel:deploy fase-1 --expires 7d`.

## Review Focus

- Producto viejo sin `updatedAt`: el cliente lo trata como `0` y no se rompe.
- Producto con `deleted:true`: no aparece en tienda, categorías ni buscador.
- Firestore caído o sin internet: la tienda sigue mostrando `catalog.json` / caché local.
- Regla nueva rechaza `updatedAt` como texto o negativo.
- `catalog.json` vacío o corrupto: el cliente cae al método actual (leer Firestore).
